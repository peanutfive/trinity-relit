## 需要先做出的实现决定

动作结果应在统一执行边界表达，不能靠章节手工减回合、跳过某个计时器或把副作用塞进描述函数。原版取镜前后207moves相同是直接可见证据；源码RFATAL用于解释其控制流，不能把名字机械映射成玩家死亡或所有失败都不计回合。存档和输出属于独立问题：已处理且有状态变化的动作即使不推进回合，也应有明确的持久化策略，不能照搬“未知输入完全不变”的处理。

平台与呼吸需要不同状态。平台计数可在当前房间onTurn按条件推进并持久化；呼吸采用可恢复计时回调，但现有GameState只有一个timer字段，须核对跨章计时器共存，不能为平台覆盖其他计时器。首次登台初始化一次，读档和重新进入不能重新发放完整寿命。聆听的主动推进与普通回合推进应分别实现和测试。

当前binoculars_broken实际上被用于坏平台分支，而原版镜子回收后仍可使用。迁移应明确平台和物品各自状态及旧存档兼容，不能仅按flag名字推断镜子损坏。镜子放置、拿取和奖励由对象状态驱动，避免靠描述文字暗示存在但实际无法拿到。

容器迁移先列对象映射、开关、大小限制、携带/穿戴、可见性和一层遍历，再编写受潮事件。原版有不同物品替换对象，现有一个bag加布尔值未必能完整表达；必须检查跨章引用。普通入水与风车坍塌的EBAG内容处理在源码中不同，坍塌组合尚未跑通，不能共用一个未经核验的“全部入水”函数。

英文从对应目标版转录取出，中文按项目格式紧随。源码分片只负责定位，不能补写连接词或用自创英文填补未知分支；原版响应、源码和完整转录继续本地隔离。对动物溺亡、WTK湿态等条件应保留专属文字检查；随机修饰语允许有限源码变体，不能放宽成任意同例程文字。
