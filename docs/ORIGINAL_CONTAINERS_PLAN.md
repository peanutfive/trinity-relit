# M4 容器与入水后果实施计划

2026-10-20。基于已推送的`d8a2f33`及41个原版场景/350检查。人类已明确授权本文列出的M4运行时与相关测试/文档；实施登记T21，分支codex/container-mechanics，不合并main或部署。研究预备登记T20。

## 目标与边界

玩家通过正常指令获得空袋、装入/取出物品、放入口袋，再经历普通入水或风车坍塌；两种路径的内容物后果、检查/收听和刷新续玩都能正确呈现。

保留全部房间ID、跨章入口和既有计分保护。本批不实现M5三种动物生死、黑暗/光源、全局跨章时钟、设备修理或完整调频。鸟笼作为已验证的容器参与；现有旅鼠flag保持兼容，不冒充完整动物对象模型。不恢复旧embedding启动路径。

## 状态与兼容契约

1. `itemLoc`继续是唯一位置真相，新增`in:<containerId>`表示直接父容器；放下袋子只移动父对象，内容不复制。关系拒绝自包含、循环和非法父对象。
2. 保留`has()`表示直接随身物品，避免封闭容器内钥匙意外通过其他章节前置。新增明确的内容物、携带根项、可见性和可访问性API，通用命令与语义候选共用判断。
3. 可见与可取分开：透明闭笼可见内容但不能直接取出。查询安全遍历关系；受潮只检查已验证深度。
4. `carryCount()`继续只计顶层手持名额。口袋和容器约束按原版SIZE/MASS/CAPACITY及算法，不能以数量或SIZE简单求和代替；未知元数据不得默认无限小。
5. BAG、EBAG、SOGGY是独立对象；替换显式选择转移或保留在不可访问旧对象中的内容，不将`destroy()`改成递归销毁。共享别名按当前可见对象消歧，不能永远命中定义顺序第一个bag。
6. 新存档拟采用v2并接受v1迁移；旧顶层位置逐项保留，新对象默认未出现，destroyed不复活，不能根据`birds_fed`猜测补发袋子。无法可靠映射的历史状态保留并记录边界。
7. `main.js`同时处理旧本地存储键、旧导入版本和引擎校验；仅在新存档完整验证成功后写新键，保留旧档以便恢复。坏档拒绝不能改活状态或磁盘。仅改engine版本常量不足以完成迁移。
