# 试玩中英对照修复（T24）

用户在Broad Walk看到初见对白有中文，紧接着循环叫卖却只有英文。目标是让现有英文叙事有完整、紧邻的中文对照，保持玩法和英文内容。

## 验收步骤

- [x] P1 审计实际输出：检查章节描述、事件、每回合/计时器、物品和共享规则；区分完全缺译、部分省译、段落排版与无调用的辅助函数。循环叫卖与引语核对本地原版来源。
- [x] P2 补齐叫卖六种变体、梭罗/卡罗尔/蒲柏引语和已确认的物品/动物省译。中文完整保留英文中的方向、门型、动作、条件与作者署名。
- [x] P3 只对能明确配对的现有长段落交错排列英文/中文；物品单换行改为空行，避免两种语言被UI归入同一段。共享规则按对应段落输出；不在UI猜测或自动补译。
- [x] P4 逐条叙事输出断言（不让同一指令的其他中文掩盖缺译）；覆盖叫卖变体、喂鸟后停止、引语、物品跨房间描述、动物条件、省译分支和长段落。真实页面核对DOM语言顺序、桌面/窄屏与页面异常，使用隔离浏览器，不重置玩家试玩存档。
- [x] P5 `npm test`、`npm run verify`通过；出口报告与既有43项基线一致。审查非中文文本与机制不变、版权数据未入库，更新记录并在开发分支交付。

## 实施边界

涉及文件以TASKS T24为准。不修改engine/parser/main/ui、房间ID、状态或存档版本。不更改既有英文措辞，也不把本轮翻译检查当成全部英文已完成原版逐句认证。原版、转录和测试页面产物仍只放忽略目录或临时目录。

静态规范校验目前只检查整份章节存在中文，无法发现局部缺译；增加面向实际输出的回归，避免重复出现同类遗漏。含中文的输出也可能漏译引语或条件，需要人工语义核对；测试通过不等于全项目逐句译审完成。

叫卖变体当前读取旧counter `turn`而非`state.turns`，未调用的nannyBlock只有英文；均为本轮不修改的既有机制/死代码，避免将翻译修复变成行为调整。
