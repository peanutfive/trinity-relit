# 道路、碰撞、出口与入场审查

2026-10-23，覆盖当前已制作19场景、66条可显示出口；依据实际背景、地面多边形、出口坐标及真实键盘操作。未制作区域不计入此范围。原版拓扑差异继续按人类决定暂缓修正。

## 原因

1. **先画背景，后把出口塞进图里。** 多个房间用四向十字路素材承载五至六个逻辑出口；没有独立支路的方向被放到主路中段。追随画面道路与追随文字箭头变成了两套玩法。
2. **把遮挡轮廓当占地。** 宫殿门柱原碰撞从153延伸到192，阻住了图中柱身后方的东路；应只阻挡216～232附近的地面基座，上部由遮挡层处理。
3. **只按可达性描地面。** 圆池塘漏掉北岸真实步道，左上多边形斜接处有急缩/碎片化；能算出一条路径不代表玩家能舒服地沿素材行走。
4. **出口只判断距离。** 花径旧起点(32,162)距西出口(16,162)仅16，而传感器半径17；按D向右走，第一小步仍在传感器内，于是误执行w返回。不是D被解析成西，也不是原地图方向错误。宫殿门/大道/花径北路还会先撞到中途的斜向出口。
5. **入场没有来源协议。** 原先每次换房都用目标房默认spawn，丢失了从哪条路进来的空间连续性；默认落点还可能直接落在返程传感器内。
6. **验收只走“指定箭头”。** 结构检查证明热点可达，点击出口的自动寻路又锁定方向，两者都可能通过，却掩盖键盘沿可见道路时的提前传送和错误方向。

## 本轮已修

- 宫殿门柱改用基座占地；人物可从门柱后方走东路，仍保留前后遮挡。
- 普通换房先按来源房间匹配目标的真实返回口，在入口内侧落地、朝场景内部；不用硬猜反方向，也不新增返程连接。66条出口均有安全视觉落点，其中60条按实际返回连接匹配。剧情运输保留专用落点。
- 自动出口必须在移动方向匹配且接近该出口时触发；远离/静止不触发，直走北路不被NE/NW传感器抢走。明确点击出口仍沿安全路走到该口。
- 圆池塘补回素材北岸步道与左上连续转弯带，NE从左上错误位置(184,52)移到右上实际小径(425,22)。池水继续阻挡，原目标仍为兰开斯特门。
- 新增来源入口、旧落点反向走、北路不误进斜口、门后通路和圆池塘真实岸路的回归。

## 后续生产门槛

### 2026-10-25 因弗内斯台专项复验

旧背景只有四个画面边界路口，代码却强放五个出口：SW在通向S的中段，E(425,126)贴在花坛旁，SE(424,247)在灌木里。地面描边也整体偏离左右弯道：旧图(70,168)、(90,190)、(130,215)、(172,240)、(355,165)、(380,190)均被判阻挡。不是按键解析错误，也不是多边形接缝算法故障。

原验收只检查“代码出生点到代码出口可以寻路”，未从画面独立取样，因此错误地面可自证通过。这次先用`assets/inverness-road-layout.svg`定义五出口路网，再生成同画风单房背景`assets/inverness-terrace-v2.png`；实际交付图没有精确保留蓝图坐标，碰撞仍须重新对图描边，不能直接套蓝图。

新W/E口(16,95)/(464,95)，SW(16,251)、S(230,275)、SE(464,275)，方向与目的地仍读取原章节。左右弯道有连续宽度，左下真实Y岔分开SW/S；末段用当地向外切线触发，避免右下路朝下却必须按东南才能离开。婴儿车停在(270,86)，保留原车身占位，从y102绕行；男孩、耳机、碟子与无快照导演回退共享锚点。

`checks/inverness-routes.test.mjs`的路径点由另一位代理从交付图独立读取，不从碰撞数据生成。`tools/browser-inverness.mjs`使用`?reviewRoutes=1`隐藏全部出口标签及其文字点击目标，以真实WASD走五条路，在无车/有车两种状态下全部往返，核对来源入口并沿反向道路走回露台。另检查旧档近点可走、手机横屏车旁通道；出入过程中不点击本房箭头。邻房返回仍使用其既有出口，不将本批验收解释为那些房间的道路美术已完成。

该房现为本地校准样本；其余房间审查与发布门槛保留。后续不得只新增一个spawn→exit寻路断言，就把画面路线标记为完成。

### 全场景要求

先暂停扩房，把已有场景的路网校准放到新素材生产之前。引擎框架不会自动修正这些问题。

1. 从现有章节列出每个出口的方向、目标与条件，画灰盒平面图；每条可通路拥有唯一出口ID、完整地面通道、传感区和对向入场点。
2. 素材按灰盒制作：出口数量、相对方位和路口形状必须一致。参考图控制画风，灰盒控制空间；不得把新增出口挤在通往另一出口的主路中途。
3. 每条画面上可见的道路都说明终点：通往既有出口、可接近的死路/景物，或明确的自然边界。没有实现的区域不能靠一个能走到画面边缘却无反应的路口交差。
4. 地面、实体基座、前景遮挡分开标注。道路转弯要有连续带宽和脚底余量，不能只在多边形尖角处接上；禁止通过扩大互动半径来掩盖不可接近的物件。
5. 先隐藏文字箭头，用普通WASD/触屏从每个入口到每个出口，再双向返回；检查途中不抢其他出口。点击箭头寻路只作为补充路径，不能替代这一验收。
6. 对每个入口检查：来自哪个房间、实际落点、朝向、传感区外安全距离；原存档落在旧传感区内时，向场景内部移动也不能误切房。
7. 一并验收机关、NPC/车体状态、手机/桌面、碰撞与视效开关。更新逐房审查记录后才批准正式美术。

运行`node prototype/2d-demo/tools/review-navigation.mjs`可检查覆盖、66出口安全入场与远离不误切，并输出逐房问题。加`--release`时，任何场景未人工批准道路体验都会失败。当前0/19获道路美术发布批准，这是保留整改要求，不是运行时检查失败；日晷顶点仅为校准样本。该门槛是本目录的独立工具，尚未接入仓库CI。
