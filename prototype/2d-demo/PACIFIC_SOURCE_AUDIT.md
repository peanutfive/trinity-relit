## 时间核实

原版 `ON-MESA-IN` 在进入太平洋上层时设游戏钟为清晨4:52，并登记潮汐与海豚事件。原始 `CLOCKER` 每次正常周期推进15秒，`I-TIDE` 在5:00发生核爆；这不是按下 PA 开关后启动的七分钟沙漏。PA 只影响声音，潮汐与核爆并不因 PA 关闭而停止。椰子约4:55落向小岛岸边、4:56浮起，后续会漂走，海豚取物依赖这些状态。

当前适配没有这套岛上时钟、潮汐或核爆。只在 `push switch` 时 `startTimer(7, "pacific_switch", …)`；引擎同一动作结束立即扣一次，所以响应后剩6回合。后续被引擎处理的动作（包括 `look`、`wait`、无路可走或看不到对象的反馈）也推进周期，动画时间和网页等待不会推进。到期设 `pacific_timer_expired`，输出提示并清除计时器；不死亡。之后按按钮只输出太迟，不设成功标志，也没有重置开关/再次挑战事件。

原版依据：`events.zil` 的 `CLOCKER`（约68–126行）、`I-FLIPPER`（约2451–2502行）、`I-TIDE`（约2504–2640行）；与 `places.zil` 的入门设钟逻辑互证。现适配以 `engine.js` 的 `startTimer` / `tickTimer` / `_postTurn` 及 `pacific.js` 的三个事件实测。

本批展示须保留上述当前状态机，不显示虚假的现实秒数、七分钟读秒条或核爆动画。暂停、读对话、开地图、网页失焦、素材播放均不可额外提交回合；跨章读档必须先登记 `TIMERS.pacific_switch` 回调，以使到期标志真实恢复。旧文案中的“分钟/信号”是原章已有债务，不能据此声称忠实还原原版。

## 本轮命令实测与验收建议

- 当前 `examine box` 输出看不到对象，耗一回合；`press switch` 不被解析器识别，耗零回合。事件虽列出 `press`，界面必须提交已支持的 `push switch` / `push button`。
- `open box` 后 `push switch` 得到剩6回合；一条 `look` 加五条 `wait` 后到期、计时器清空、主角存活，随后 `push button` 不成功。另分支及时 `push button` 应清计时、设成功、不设到期。
- 箱体第一次 F 由玩家主动 `look`、观察后再 F `open box`；此时尚未启动计时，两个动作仍照原引擎正常结算。开箱后才让两个内部控件分别可命中，开关和已满足条件的按钮直接提交 `push`；不自动附加无效 `examine`、`look` 或额外确认。尚不能操作或已操作的控件只保留当前受支持的环顾反馈；到期后的按钮仍提交合法事件以获得太迟反馈，不伪造复位。
- 东滩现 `onEnter` 使用“未携带且不在当前房间”判断；若椰子已丢在另一房，重进东滩会将同一个 ID 搬回东滩。这是原章位置债务，表现必须服从真实状态，不偷偷复制或固定椰子。
- 航向/道路测试应覆盖全部普通出口与来源返回位、上下层 F、白门进出、开箱各控件不重叠、持物操作、及时/到期两分支、计时中保存恢复、M/暂停冻结及手机界面；不能用“核心通关测试通过”替代画面道路实走。
