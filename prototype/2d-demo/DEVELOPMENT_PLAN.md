# Trinity Relit：HD-2D 改编开发计划

版本：2026-10-27。状态：人类已确认原版式文字版与HD-2D改编版两条产品线，并授权继续2D后续章节。空间与探索要求仍遵循[修订计划](EXPLORATION_PLAN.md)。

## 双版本与本轮推进

文字版保留`prototype/index.html`的命令输入玩法，以原版规则和叙事还原为目标；2D版使用`2d-demo/index.html`的场景探索、F互动和叙事演出。二者保留独立入口和存档，不因图形化需要覆盖文字版行为；共享核心的修正规则须另行审查，不能直接把dev机制改动混入2D。

本轮恢复章节扩展：先完成Wabe楼梯底部→弯道→荒野蘑菇门→日本游乐场/避难所→荒野的实际往返切片。已有日晷符号控制门，物品与章节切换仍只经原引擎。新场景须先灰盒、后出图、再按交付图复核道路、脚点、物件和遮挡；未制作的相邻区域在接近路口时明确显示制作边界，不添加替代捷径或提前泄露解谜动作。

本计划落实新的 2D 产品方向，不取代 AGENTS.md 的项目规则。现有文字版与内容修复记录仍保留；原版文本、地图真值、文件锁、版权隔离与人工合并要求继续适用。

## 1. 最终产品与当前边界

制作可操控人物的斜俯视 HD-2D 文字冒险：在场景中行走、接近并互动，以原版叙事、物品与机关推进 Trinity。当前三场景图集是人类认可的美术参考：细密材质、写实尺度、暖阳冷影、安静的电影感。角色不是战斗主角，不添加原版没有的战斗、任务对白或英文剧情。

当前可图形操作跑完11房序章、Wabe 10/30房、日本游乐场/避难所2房，具备独立2D存档，共23场景。日本章交伞、折纸与纸鸟返程已接现有规则；详见[JAPAN_PRODUCTION.md](JAPAN_PRODUCTION.md)。已有场景均有多边形地面约束，局部前景遮挡已接入，其余空间/美术审查仍待完成，不能将章节扩展解释为旧地图整改结束。

**2026-10-23调整：先打磨已有场景的空间与探索，再扩大章节。** 用接地、占位与遮挡解决“贴图随意移动”；去掉解谜动作列表，改为观察对象、选中手持物品、点击目标试用；纸船与纸鸟保留同一对象身份。推荐后续试迁移Phaser表现层，当前尚未引入游戏框架。具体顺序和验收见EXPLORATION_PLAN.md。

**同日道路纠正：** 已审查19场景66出口，背景路网与出口数量/位置存在普遍错位，详见SCENE_ROUTE_AUDIT.md。后续先做出口灰盒，再按灰盒制作美术；隐藏文字箭头的真实键盘/触屏双向行走为正式准入，不能只用“热点可达”和点击箭头流程。现有全序章跑通属于表现原型，不能据此宣称正式空间体验完成。

**2026-10-22人类调整优先级：先完成2D表现，暂缓原规则修正。** 已核对出的鸟食、涉水、白门等现有规则差异保留在PROLOGUE_PRODUCTION.md，不改受保护模块。允许沿现有运行时先制作可玩的表现版；原版忠实性仍是独立验收，未满足时不称全部还原。结束本轮后上传开发分支，再推进Wabe下一批。

交互基线：探索画面不显示常驻键位栏、方向、互动或Esc按钮。默认F统一互动与对话，优先面朝的附近目标；空处按F不自动环顾，L用于环顾。M查看章节地图，Esc打开暂停菜单，包含键位、画面、声音设置；背包与提示由快捷键或菜单打开。鼠标/触屏点地行走、点对象互动，右键或双指轻触打开菜单。菜单关闭后回到原场景、原对话页和原状态。

## 3. 技术架构与文件边界

当前保留纯静态 ES module、无构建、无运行时第三方依赖。后续Phaser表现层试迁移是单独批次，尚未实施。2D表现层只提交既有命令，游戏状态仍由现有GameEngine决定。移动像素、菜单、画面和动画不推进原版回合；执行动作与跨房间命令才使用现有回合路径。

| 模块 | 职责 | 计划文件/目录 |
|---|---|---|
| 场景清单 | 房间 ID、背景分层、出生点、出口触发区、碰撞、互动对象与来源状态 | `scene-manifest.js`，后续 `scenes/` |
| 世界与镜头 | 逻辑坐标、移动碰撞、相机投影、缩放、出入口落点 | 后续 `world.js`、`camera.js` |
| 渲染 | 地面、远景、按脚底排序的角色和道具、可遮挡前景、光影与粒子 | `art.js`，后续 `render/` |
| 人物动画 | 四方向姿态、位移步态、idle、查看/拾取、后续推车等 | `character.js`，后续 `actors/` |
| 引擎适配 | 命令串行化、事件输出、章节加载、TIMERS 登记、状态到视觉的映射 | 从 `game.js` 提取到 `engine-adapter.js` |
| 图形互动 | 热点可达、单次观察/触碰意图、手持物品指向目标、对象认知 | `interaction-intent.js`、`discovery.js`；后续独立背包模块 |
| UI 与设置 | 原版文本分页、暂停、改键、画面/音频设置、手机输入 | `index.html`、`style.css`、`settings.js`、`audio.js` |
| 存档 | 现有引擎快照 + 2D 扩展坐标和版本，偏好独立保存 | 后续 `save.js` |
| 验证 | 场景结构、对象映射覆盖、可达性、引擎/图形路线一致、浏览器验收 | `tools/`、`checks/` |

以上路径均相对于 `prototype/2d-demo/`。首先在已授权目录内推进，正式入口、目录迁移或 CI 接线另登记文件范围。不得因本计划而直接修改受保护的 engine.js、parser.js、items.js 或章节数据；需要修复时先整理证据、最小改动和验证方案，由人类明确授权并解决文件锁。

图形模式与文字模式不各建一套 flags、道具位置、出口条件或计时器。异步命令同一时刻仅执行一个；读档不得重放 onEnter 副作用；章节加载必须登记 TIMERS。

## 4. 美术与动画规范

### 场景生产

1. 先核实房间身份、出口、描述与状态分支，制作灰盒并跑通互动，再做正式美术。
2. 当前拼接图集保留作参考，正式场景按独立资源组织：地面/远景、静态中景、角色与移动道具、可遮挡前景、环境效果。过门、树冠和长椅前沿需要有可验证的遮挡关系。
3. 可拾取、移动、打开、变化或尚未揭示的对象不得烘焙在背景里。足球、纸鸟、雨伞、婴儿车等由引擎状态控制显隐和状态。
4. 每个互动对象有稳定 ID、原版对象/事件引用、脚底锚点、碰撞形状、互动区域、排序点、显隐条件。所有几何共用世界坐标，清晰度和屏幕尺寸只改变投影。
5. 共享花园地面、植被、建筑套件，仍保留各房间辨识度。不用换色图冒充不同房间，不一次性生成全部背景。
6. 原创素材记录实际提示词、生成方式和人工选择；不得使用商业游戏的原图集、角色或 UI 资源。

### 人物与表现

- 当前标尺：480×288 逻辑画面，主角约 35 逻辑像素高，脚底锚点固定；四方向头身比例、帽沿、衣料与配色一致。
- 基础动作：四方向 idle、walk（至少八个可检查相位）、查看、拾取；按序章真实机制增加推婴儿车、撑伞、涉水，其他章节按实际需要扩展。
- 步态由实际位移推进，斜行不加速，碰撞不踏步，转向不漂移，停步收势。暂停时动作时间、游戏回合和状态同时停住。
- NPC 要有符合场景的坐姿、停留和离场状态。老妇人不长期复用站立主角动作；鸽子、车轮和道具状态独立。
- 镜头先固定构图，完成碰撞/遮挡/状态一致后再增加克制的跟随或推移。视觉景深不能模糊关键线索和互动目标。

### 大道叙事表现资产包（人类反馈补充）

文字提到的关键对象与事件需要在画面中得到反馈，但不把每句描写都制作成独立过场。世界内人物、道具、事件动画优先；人物/道具特写作为查看时的补充，不强制打断行走。

| 内容 | 必需的场景表现 | 可选特写 | 触发与验收 |
|---|---|---|---|
| 卖鸟食的老妇人 | 独立坐姿、呼吸/招呼、递出鸟食与找零，肩上停鸟 | 查看时静态半身像或面部插图，表现皱纹与神情 | 关联 examine_woman_bw / buy_bag；不能只放通用站立像素角色；喂食后是否离场须先核实原版，不由当前文案消失推断 |
| 鸽群 | 地面聚集、啄食、腾起/盘旋的有限动画，依状态控制密度 | 通常不需要独立特写 | 关联 examine_pigeons_bw / feed_birds；聚集与吃食可见，不提前暴露藏在鸟食里的线索 |
| 红宝石 | 可独立显隐的地面道具、红光与切面闪烁、查看用放大图 | 查看时道具插图，有助于小屏辨认 | 仅 ruby_visible 且非 ruby_snatched 时出现；不能烘焙进背景；尝试拿取不应先把它加入背包 |
| 叼走宝石的大鸟 | 独立于鸽群的较大鸟角色，从树后冲出、叼取、绕行、向东离开 | 通常用场景动画即可，无需再加肖像 | 既有 take_ruby 文本说它外形像走鹃、在游客间跑过；须核实原版后按该动作制作，不能默认改成鸽子飞走 |
| 老妇人惊呼与风向变化 | 神情/姿态变化；树叶先停、再表现来自西方的新风，配合原版文字 | 可复用半身像的小幅表情差分 | 与 take_ruby / wind_changed 同步；未触发前不预演 |

事件演出由引擎成功执行对应动作后驱动，视觉不另改 flags。演出期间不多消耗回合，可暂停；F/点击对话框只翻页，跳过需单独点击明确按钮，跳过后显示与引擎一致的最终状态。读档不得再次发宝石、重复加分或重放已完成事件。

生产顺序：先灰盒跑通购买鸟食 → 喂鸟 → 红宝石出现 → 尝试拿取 → 大鸟叼走 → 风向改变，再接入统一素材与短动画。此链和其余序章主要事件现已落地；制作矩阵、原版来源与暂缓差异见PROLOGUE_PRODUCTION.md。

### M2 的下一组具体任务

- M2.1（本轮已落地默认状态结构检查）：场景清单拆出出生点、出口、碰撞与热点；让渲染、移动和审计读取同一配置。清点工具标注三个场景的原版证据仍待补全。
- M2.2：先明确原引擎 look、examine 与图形面板动作的回合语义（当前环顾直接 describeRoom，与 processInput 的回合路径不同），再从 game.js 提取输入/世界移动/引擎适配，保持现有图形流程及 22 项回归不变；加入命令失败与异步切章的场景恢复。
- M2.3：背包选物品后指向目标试用，观察与触碰按当前对象状态执行；已替代旧动作菜单。通用放下与更多近看操作待制作；不能靠UI直接修改引擎状态。
- M2.4：首四场景门柱/长椅/花丛遮挡与19场景地形、实体占位已接入；继续制作其余前景，正反方向检查排序。后续Phaser试迁移保留同一空间配置。
- M2.5：补三场景原版分支证据；完成正式美术准入后，选择下一组相连房间制作灰盒。

### M3 序章流程验收

覆盖足球、日晷指针、纸鸟展开阅读、购买面包屑、喂鸟、红宝石/风向、婴儿车路线、雨伞与足球事件、进入车内/撑伞、Long Water、涉水与白门切章。顺序和条件以原版核实结果为准，不以清单顺序替代游戏逻辑。

核对首次/再次进入、道具持有与缺失、可见但不可取、失败/重复动作、倒计时与死亡。对暂停、动画、缩放、改键和设置进行回合不增长检查。接通所有原版出口，不增加捷径。

### M6 区域生产顺序

先做 Wabe 的一条完整往返路径，再逐个补齐蘑菇门。Underground、Tundra 可优先做内容核实，Japan、Pacific、Islet 逐条补地图/事件；Orbit 先解决推进方式；Desert 先补对象映射；Ranch 地图与文本一起复核重做；Finale 以完整主线验证作为准入。技术工具的维护顺序与美术制作顺序分开，未核实区域不阻塞已核实区域的开发。

## 6. 忠实性与版权的内容准入

每条房间描述、examine、成功/失败反馈、计时器、死亡和切章文本需正向出处。记录原版文件哈希、工具版本、对象号、进入命令、道具/flag/计时条件、transcript 范围与事件引用。英文只做明确的排版归一化，中文逐条对应，缺证据标为待核实，不写英文占位。

原始 DAT、transcript、提取 JSON、出口真值等保持本地隔离，不能提交。入库的审查记录仅含允许公开的定位元数据、覆盖范围和结果，仍需提交前检查。筛查脚本或模型判断不替代原文出处。

区域正式美术准入须满足：房间身份已确认；主线出口/目标/条件无未决错误；必需机制无缺失；英文有出处。旧测试能通关、旧偏差未增加都不单独满足该门槛。

### 中文译文稳定性

同一原文条目与同一状态分支使用固定中文，试玩运行时不实时翻译，美术/界面迭代不得顺带重译。建立稳定文本 ID 与中英对应台账、房间/物品/术语表；中文修订单独记录前后差异，禁止把不同状态的原文分支误当成译文随机变化。验收比较完整文本内容而非仅截图分页位置。当前三场景在相同 GameState 下重复读取 desc 的文本完全一致，人类后续提供的花径截图已定位为房间描述与物品注释重复，并在显示层修复；这不代表全部译文已经完成统一审核。

## 7. 验证标准

- 规则层：npm run verify 通过；存在测试时 npm test 通过；本地有 DAT 时 npm run verify:exits 不增加偏差，并另跑目标区域更完整的真值审计。未修的旧问题明确列出。
- 2D 配置：唯一 ID、有效房间/事件引用、出口方向与目标、出生点/互动区可达、碰撞与遮挡锚点一致、资源加载失败可恢复。
- 浏览器：按真实键鼠/触屏路径走完整交互链，检查控制台、截图和 render_game_to_text。走路/转向/停步/碰撞、暂停/改键/设置、背包/双对象、切章/存读档均覆盖。
- 路线一致：同一初始状态下，图形操作与命令回放到达的房间、道具位置、flags、分数、回合与计时器一致。
- 显示与可访问性：390px 手机和桌面无横向溢出；文字不截断；菜单焦点可循环且 Esc 返回；高/低清晰度共享几何；游戏控制不依赖颜色或 hover；设置不可用时显示真实状态。
- 性能预算先作为目标：常见桌面争取稳定 60fps、手机至少 30fps；首屏只加载当前区域素材，后续按场景/章节加载并释放。对真实设备测量后再确定可承诺的素材与内存上限。
- 发布：干净分支、版权与范围检查、验证回执、截图；人类开 PR 并合并。未经人类要求不推送或合并 main。

## 2026-10-23 视觉整合验收规则

本轮人物、地图及浏览器适配反馈揭示了共同根因：只验证模块能运行，没有同时校准素材锚点、家具前景和最终游戏画幅。后续新增场景/事件必须遵守以下验收要求：

- 人物按头顶、脚底、坐面分别标定，伞冠/帽饰不计入人体身高；使用actor-layout统一绘制比例、点击范围和手部动作锚点。坐姿不能简单缩放站姿高度；须与同景主角并排检查。
- 长椅背板、座沿、扶手、椅腿分别定义深度。座位上的人物在椅背前、座沿后；铁栏孔洞保持透明，禁止把包含地面的整个四边形当作实心遮挡。本轮宫殿铁门使用源图深色材质遮罩与轻度淡化，仍为现有背景的近似；正式前景分层应由独立透明素材替换。
- 人物携带或使用的道具与素材动作共用锚点。碟子在男孩伸手可及处、泡从嘴边起，不绘制第二份独立碟；雨伞脱手前后位置衔接，静态与事件角色身份一致。
- 至少验看人物静态、动作首/中/尾、主角前后经过的截图。对栏缝后主角可见性增加实际像素检查，不能仅靠命令执行成功判断画面正确。
- 游戏与地图共用stage，普通窗口和全屏保持480:288场景比例，完整显示画面不拉伸、不裁掉交互区域。地图/暂停在stage内，不另用全页网页弹窗；390×844、844×390、1024×768、1366×768及全屏检查不溢出。
