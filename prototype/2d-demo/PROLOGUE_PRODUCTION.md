## 1. 本轮实际验证结果

- 使用 `scripts/commands_prologue.txt` 在本地 dfrotz 重放，实际依次进入全部 11 个序章房间及 Meadow；原版得分 7、23 回合。
- 加入日晷指针与纸鸟取得/展开/阅读的第二条路线，同样成功进入 Meadow；原版得分 15、29 回合。
- 重跑 `scripts/crawl_real_map.mjs`：100 次 dfrotz 运行，得到默认状态 9 房、38 条可通出口。该部分与现有序章的直接出口一致；它不覆盖 Long Water/Wading 和所有条件分支。
- 独立分支确认：买完鸟食尚未拿到袋子；没有拿袋子时喂鸟失败。Long Water 反复向南仍在岸上；使用涉水动词进入 Wading。刚涉水时白门尚不可见；继续等待后导弹及白门分步出现，之后可入门。
- 实测宫殿门持续等待及抵达 Long Water 后持续等待，均能进入原版死亡路径；首种路径出现防空警报。
- 初次 `f9473bd` 基线的 `npm test` 为 22/22；同步后在 `57c5f9d` 重新实跑为 **82/82**，实现侧通关及新增撑伞老妇互动回归通过。测试数量变化来自主分支已合并的工作，并非本报告改动。但运行时能通关不表示与原版的全部状态/文本一致。

当前清点：11 房、53 个章节事件条目，另有 `onEnter`、`onTurn`、计时器与条件出口。不能仅做 53 个静态文本按钮就宣称完整 2D 序章完成。新增的是 `help_umbrella_woman` 与 `approach_womans_umbrella`，均调用同一一次性老妇事件收尾函数。

### 涉水指令的最小文件范围

`57c5f9d` 的 `Parser.parse('enter water')` 已可解析成 `enter + water`，但序章没有接它的事件。`swim`、`wade`、`游泳`、`涉水` 仍均返回 `null`。新版本支持 `help the old woman` 和 `hold umbrella`，并省略名词短语开头冠词；这不等于已支持涉水词。

- **只为图形界面接正确涉水动作**：可在获授权的 `prologue.js` 增加 `enter water` 对应事件，2D 按钮提交现解析器已支持的命令；不必为此修改解析器。
- **同时支持原版及中文手动输入词**：还需单独授权 `prototype/js/parser.js`，最小增加 swim/wade 及中文别名的明确解析；并增加与序章的回归，不借机调整其他语法。
- `engine.js` 不需要为以上提案改动。`items.js` 原字段也不应为了省事重写；待领取/已喂食状态可由章节事件与 state API 表达。

## 5. 全章统一画风约束

1. 人物、肖像、道具、动物、过场共享已认可的暖阳/冷树影、细密材质、克制色彩、斜俯视透视和尺度。不能背景细腻而事件使用粗方块、彩色贴纸、不同光源或现代卡通脸。
2. 原版中的两位老妇分别建角色 ID、立绘/坐姿与肖像：Broad Walk 卖鸟食的老妇，与 Lancaster Gate 的撑伞老妇。不能因两者中文都叫老妇而共用脸。
3. 冲来叼宝石的大鸟与鸽群分开；原文对其走鹃外形带有不确定口吻。大道段落以跑出/穿行/向东离开为动作依据，不能自动改成鸽子飞走。白门处再次出现该鸟的现有文本需另证。
4. 红宝石、纸鸟、伞、球、婴儿车与掉落物不烘焙进背景；状态改变通过独立资产表现。每件资产有统一脚底/接地点与遮挡排序。
5. 大道鸟群、男孩泡泡、伞上树、乘车失控、湖中导弹/白门均是全章事件资产，不只制作一个红宝石片段。复用导演/时间轴能力，具体运动由事件数据驱动。
6. 所有演出可暂停、可跳过；跳过不跳过原规则动作，不重复给物品/加分。暂停和图形动画不自增游戏回合；场景切换和存读档后恢复唯一正确的最终状态。
7. 查看特写放大关键脸部/物件时仍保持同一材质与配色。先让世界内动作可理解，再添加肖像与道具特写，不把每句文本强制变成全屏过场。
