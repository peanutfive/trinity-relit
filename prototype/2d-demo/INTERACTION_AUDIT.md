# 探索目标与输入审查

2026-10-24。范围：当前19场景的2D目标选择、点击与走近请求；不改原引擎、解析器、章节规则或出口。

| 问题 | 根因 | 本批修正 |
|---|---|---|
| 身后较近物件抢走F目标 | 键盘只按脚底距离排序，没有朝向 | 先排除背后目标，再综合距离与朝向；脚边8像素保留容差。提示与F读取同一结果 |
| 宫殿门隐藏的“自己”可被F选中 | 鼠标单独排除ID，键盘未检查visual:false | 两种输入共用显隐/可执行动作检查；仅演出对象也不接收操作 |
| 点足球旁空地会查看足球 | 小物件继承20×20半径，远大于约10×10的素材 | 分离可点击形状与可交互距离；校准球、宝石、纸鸟、木片、碟子等，触摸增加有限容差 |
| 点碟子或耳机容易被男孩身体抢走 | 大对象与细部只比较归一化命中距离 | 重叠时优先精确细部，保留男孩身体范围和日晷指针/环/盘的分层优先级 |
| 树上已撑开伞的伞沿点不到 | kind仍为umbrella，误套收伞形状；挂树使用握持锚点 | 在场景配置中声明开伞轮廓，不把脚底、握持点与可见中心混为一谈 |
| 改向时仍突然弹出旧物品对话 | 到达检查早于本帧手动移动；新点击失败时旧请求可能残留 | 手动输入先取消旧请求；新点击先清除旧路径、旧出口和到达后操作，再计算新路径 |
| 空处按F弹出长篇场景文字 | 无附近物件时回退为describe | 空处F不执行，环顾继续用L；不额外添加提示文案 |

自动走近和明确点击共用最终距离与显隐检查；明确点击已选择目标，不再受键盘朝向筛选。纪念碑、树梢伞和湖面白门的远景观察距离保留，岸边取纸鸟仍可用。

后续制作必须同时声明地面占位、绘制锚点、命中形状与交互距离；它们表达不同含义，不能用一个大圆统一代替。命中校准须验看素材不透明部分，至少检查中心、边沿与旁边空地，并在实景里尝试重叠细部。

本批没有建立通用隔墙交互系统。静态物件可能位于树梢、水面或实体基座上，直接要求“脚底到物件中心整段可走”会误禁正常操作。后续需为这类物件配置手部接近点/岸边观察点，再验证遮挡和路径；不以本批距离检查宣称该项完成。

验收：`checks/interaction-targets.test.mjs`，`tools/browser-interactions.mjs`。后者通过正常存档导入与真实F/鼠标/触摸，覆盖11个操作场景，包含到达同帧改向的取消检查。序章→Wabe八房、道路与事件动作由原有浏览器脚本回归。收据与截图保存在/tmp，不提交存档或转录。
