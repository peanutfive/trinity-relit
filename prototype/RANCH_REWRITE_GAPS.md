# Ranch 重写：仍需原版映射或状态支持的部分

2026-10-19更新。原有26个房间ID保持不变，另补原版Front Deck #6，共27间。默认英文按原版来源重组；本批增加经原版动态核验的风车/呼吸机制，未将所有条件方向当作全部还原。执行与验收记录见 `RANCH_REWRITE_PLAN.md`。

## 房间集合与跨章出口

原版 **Front Deck（对象 #6）** 已实现为 `front_deck`。从现有房间通向它的九条出口已补：`front_yard` 的 `w/u/in`、`assembly_room.e`、`se_room.e`、`ne_yard` 的 `s/u`、`se_yard` 的 `n/u`。平台自身 6 条固定可通行出口、两扇门控制的 `w/in` 和两条石墙阻挡已按对象属性与 `0x28588`、`0x2865c` 等动作例程接入。

另有 **28 条**出口进入 Desert / Foothills 的同名通配房间。`CHAPTER_PLAN.md` 尚未给这些房间的对象号与实现 ID 建立一一映射，因此没有猜目标。`nw_ranch.n` 暂保留到 `behind_shed` 的现有返程桥；原版该方向指向 Foothills #225。`nw_ranch.nw` 确认直达 Shallow Crater #456，已接入。Desert 进入 Ranch 的 `behind_shed.s` 未修改。

`scripts/verify_exits_static.py` 将目标对象号没有实现 ID 的出口计入「无法比对」，并在 JSON 明细的「未映射目标」中列出。当前 Ranch **98 条已映射固定可通行出口一致、0 缺失、0 目标错误、0 凭空；9 条条件方向和 28 条跨章未映射目标单列**。显示的 100% 仅是 98 条可比出口的一致率，不能解释为原版 Ranch 地图全部还原。

## 原版条件与当前状态的差异

- 壁橱门的开关有现成的 `closet_door_closed` 标志，`closet` 和 `assembly_room` 的描述按原版分支切换。Front Deck 的左右门与对应两间室内房前门已共用状态标志，开关与描述会同步，并随存档持久化。其他门的原版开关属性尚无对应状态标志，描述仍使用原版初始状态；门的开关行为需另行建模。
- 厨房原版橱柜里起初有一把牛排刀。当前 `items.js` 的 `knife.start` 是 `null`，也没有橱柜容器。本轮没有改物品系统；描述只在 `itemAt("knife") === "cupboard"` 时使用原版的单物品片段。当前默认显示的是原版橱柜空时的分支。
- 风车坍塌现在设置`ranch_landing_collapsed`，描述与禁止再登同步；兼容读取旧`binoculars_broken`。新状态表示平台损坏，镜子回收后仍可佩戴。镜子初始在windmill，旧档缺失位置沿既有items.start补齐；明确destroyed的位置不复活。人工注入旧坏平台flag同时没有镜子位置的异常旧档不自动猜测其历史落点。
- Underwater 的原版可见描述由照明条件控制。当前引擎没有完整的水下光照状态，故显示已核对的有灯笼分支；未为无光状态编造英文。
- 水库`d/in`、水下`u/out`和风车下`u`已接入首批呼吸/平台副作用；水下9个失败方向不推进气息，取镜坍塌已处理但不推进普通回合。平台/呼吸用持久计数，读档恢复与普通章节计时器独立。静态工具仍将9条条件方向单列，其数量不代表迁移完成率。
- 蓄水池边缘`n/in`的完整物品受潮、容器内容物及动物替换尚未进入运行时；风车当前仅移动扁平inventory与平台物品，不实现BAG/EBAG/SOGGY、WTK湿态或笼内动物后果。原版两种入水路径的区别已研究，不能共用未核实的副作用函数。
- 屏息当前仅在Ranch注册，出章成功后清理。这是本批边界策略，不等于原版全局队列；完整跨章调度与黑暗条件仍待迁移。帮助/背包/分数以及全游戏WAIT/绝对moves也未全面对齐原版。

原版 `.DAT`、反汇编文本和派生真值文件均只在本地使用，不随本文件提交。
